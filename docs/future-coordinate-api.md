# 미래좌표 OpenAI API 연결

## 1. 로컬 연결

1. OpenAI Platform에서 프로젝트를 만들고 결제 수단을 등록합니다.
2. 프로젝트 API 키를 새로 만듭니다.
3. 프로젝트 루트의 `.env.local`에 아래 두 줄을 추가합니다.

```dotenv
OPENAI_API_KEY=여기에_발급받은_키
OPENAI_MODEL=gpt-5.6-terra
FUTURE_COORDINATE_AI_ENABLED=false
```

API 키는 브라우저에 노출되면 안 됩니다. `NEXT_PUBLIC_` 접두사를 붙이지 말고 Git에도 커밋하지 않습니다.

`FUTURE_COORDINATE_AI_ENABLED`는 결제 검증이 구현되기 전까지 운영 환경에서 `false`로 유지합니다. 현재 코드는 개발 환경에서만 실제 API 테스트를 허용하며, 운영 환경의 무결제 API 호출은 차단합니다.

4. 로컬 개발 서버를 다시 시작합니다.
5. 인터뷰를 완료한 뒤 개발 환경에서 `/future-coordinate/result`로 이동합니다. 상단 상태가 `AI 분석 완료`이면 실제 API 결과입니다.

`/future-coordinate/result?preview=1`은 개발 환경에서만 API 키 없이 디자인을 확인하기 위한 예시 화면입니다. 실제 인터뷰 분석 검증에는 쿼리의 `preview=1`을 제거합니다. 공개 상품 안내는 `/future-coordinate`에서 제공합니다.

## 2. 현재 생성 기준

- 질문 문장과 답변을 함께 API에 전달합니다.
- 답변 근거가 서로 다른 미래 장면 3개를 선택합니다.
- 각 장면은 2~3문장의 장면 재구성과 의미, 핵심 가치, 현재의 단서, 핵심 통찰로 구성합니다.
- 세 장면을 관통하는 하나의 방향을 분석합니다.
- 하나의 방향을 기준으로 통합된 30일·90일·365일 로드맵을 제안합니다.
- 각 기간은 핵심 목표 1개, 실행 행동 최대 2개, 결과 상태 또는 결과물 1개로 제한합니다.
- 72시간 첫 행동은 인터뷰에서 사용자가 직접 말한 작은 습관을 우선하여 60분 이내의 행동으로 제안합니다.
- 응답은 JSON Schema로 고정하여 화면에 필요한 필드가 누락되지 않게 합니다.
- 한 요청의 최대 출력은 5,200토큰으로 제한합니다.
- 응답의 `usage`에는 입력·출력·전체 토큰 수가 포함되어 비용을 추적할 수 있습니다.

## 3. 유료 서비스에 연결할 때

`/api/report` 호출 전에 서버에서 결제 완료 여부를 확인해야 합니다. 브라우저가 보내는 `paid: true` 같은 값만 믿으면 안 됩니다.

권장 흐름은 다음과 같습니다.

1. 결제사가 결제 성공을 서버 웹훅으로 알립니다.
2. 서버가 주문 번호, 결제 금액 2,900원, 결제 상태를 저장합니다.
3. 미래좌표 요청 시 로그인 사용자 또는 일회용 주문 토큰과 결제 기록을 서버에서 대조합니다.
4. 동일 주문은 같은 분석 결과를 반환하여 새로고침 때 API가 중복 호출되지 않게 합니다.
5. 실패한 요청만 제한적으로 재시도하고, 성공 요청의 토큰 사용량과 모델을 함께 기록합니다.

## 4. 실제 결과 검토 체크리스트

- 세 장면이 서로 다른 내용이며 인터뷰의 구체적인 표현에 근거하는가?
- 각 장면이 삶의 모습, 변화의 증거, 다음 확장의 서로 다른 역할을 하며 사실을 새로 지어내지 않았는가?
- 세 장면을 관통하는 방향이 답변 전체의 패턴에 근거하는가?
- 30일 행동은 현재의 시간과 도구만으로 시작할 수 있는가?
- 90일 행동은 30일에 발견한 기준을 작은 실험으로 이어가는가?
- 365일 행동은 미래의 결과를 요구하지 않고 지속 가능한 상태를 축적하는가?
- 각 기간의 행동이 2개 이하이며 수량, 빈도, 기한 또는 완료물이 포함되는가?
- 72시간 행동이 인터뷰 속 실제 습관에서 나왔고 60분 안에 끝나는가?
- 세 기간에서 같은 행동이 반복되지 않고 앞 단계 결과가 다음 단계로 이어지는가?

처음에는 실제 인터뷰 10건 정도를 같은 체크리스트로 평가한 뒤 프롬프트를 조정하는 것이 좋습니다.
