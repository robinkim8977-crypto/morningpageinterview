# 결제·AI 흐름 자동 테스트

## 실행

전체 테스트:

```bash
pnpm test
```

결제·AI 통합 테스트만 실행:

```bash
pnpm test:integration
```

## 비용 안전성

통합 테스트는 `NODE_ENV=test`에서만 허용되는 로컬 대체 주소를 사용합니다. 테스트 안에서 `fetch`를 가로채 다음 서비스를 메모리 기반 가짜 구현으로 바꿉니다.

- PortOne 결제 조회
- Upstash Redis 결제 사용 장부
- OpenAI Responses API

운영 및 개발 환경에서는 대체 주소를 무시하고 공식 PortOne·OpenAI 주소만 사용합니다. 따라서 테스트 중 실제 카드 승인, OpenAI 토큰 사용, 운영 Redis 변경은 발생하지 않습니다.

## 현재 검증 범위

- 카드·카카오페이·네이버페이별 채널 선택과 PortOne 요청값
- 설정되지 않은 간편결제 수단 자동 숨김
- 기존 카드 채널 환경변수와의 하위 호환
- PG 결제 취소·실패 문구 원문 유지
- 정상 결제 승인 확인
- 정상 결제 후 AI 리포트 생성과 장부 완료
- 같은 결제번호의 반복 생성 차단
- 동시 생성 요청에서 OpenAI 1회 호출 보장
- OpenAI HTTP 오류 후 자동 재호출 차단
- 운영자의 1회 재시도 승인 후 정상 완료
- 결제 금액 불일치 시 Redis·OpenAI 미호출
- 승인되지 않은 결제의 완료 처리 차단
- OpenAI 응답 형식 오류 후 자동 재호출 차단
- Redis 장애 시 OpenAI 미호출
- 운영 복구 비밀키 인증
- 장부의 원자적 상태 전이와 복구 이력

## 아직 실환경에서 확인할 항목

다음 항목은 카드사 심사가 끝난 뒤 소액 실결제와 취소로 최종 확인합니다.

- 실제 KCP 결제창의 카드사별 노출 상태
- 카카오페이·네이버페이 각각의 실제 승인과 취소
- 모바일 앱카드에서 결제 후 사이트 복귀
- 카카오페이·네이버페이 앱 이동 후 사이트 복귀
- 실제 승인 내역의 PortOne 서버 조회
- 실제 결제 취소와 카드 승인 취소 반영

실결제 확인 전에는 금액, 상품명, 운영 결제 모드와 환불 수단을 다시 확인합니다.
