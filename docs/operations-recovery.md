# 결제·리포트 운영 장애 복구

## 목적

`/admin/recovery`는 PortOne 결제번호를 기준으로 결제 승인 여부와 AI 리포트 생성 장부를 함께 확인하는 비공개 운영 화면입니다.

운영자는 다음 두 작업만 할 수 있습니다.

1. 생성 시작 후 30분 이상 `processing`에 남은 기록을 `failed`로 전환
2. 원인을 확인한 `failed` 기록에 1회의 재시도 권한 부여

완료된 기록은 다시 생성할 수 없고, 재시도 권한은 같은 인터뷰 답변에만 사용할 수 있습니다. 두 요청이 동시에 들어와도 Redis의 원자적 상태 변경으로 한 요청만 권한을 소비합니다.

## 최초 설정

다른 비밀키와 재사용하지 않는 32자 이상의 값을 `ADMIN_RECOVERY_SECRET`에 설정합니다. 권장 생성 명령은 다음과 같습니다.

```bash
openssl rand -hex 32
```

Vercel의 Production 환경에는 다음 값이 모두 있어야 합니다.

- `ADMIN_RECOVERY_SECRET`
- `PORTONE_API_SECRET`
- `NEXT_PUBLIC_PORTONE_STORE_ID`
- `KV_REST_API_URL` 또는 `UPSTASH_REDIS_REST_URL`
- `KV_REST_API_TOKEN` 또는 `UPSTASH_REDIS_REST_TOKEN`
- `PAYMENT_USAGE_HMAC_SECRET`
- 필요할 경우 `PAYMENT_LEDGER_NAMESPACE`

비밀키는 메신저, 이메일, 고객문의 내용에 붙여 넣지 않습니다. 브라우저의 운영 화면에도 저장되지 않으므로 페이지를 새로 열 때 다시 입력합니다.

## 운영 화면 사용 순서

1. 배포 주소 뒤에 `/admin/recovery`를 붙여 접속합니다.
2. `운영 복구 비밀키`에 `ADMIN_RECOVERY_SECRET` 값을 입력합니다.
3. PortOne 콘솔이나 고객문의에서 확인한 `결제번호`를 입력합니다.
4. `상태 조회`를 누릅니다.
5. 결제 승인 상태와 리포트 생성 기록을 함께 확인합니다.

복구 사유에는 이름, 이메일, 인터뷰 답변 같은 개인정보를 쓰지 않습니다. `OpenAI 500 오류 확인`, `배포 중 서버 중단`처럼 장애 원인만 적습니다.

## 상태별 처리

### 생성 기록 없음

결제가 정상 승인이라면 고객에게 결제한 브라우저에서 미래좌표 결과 화면에 다시 접속하도록 안내합니다. 아직 OpenAI 요청은 시작되지 않은 상태입니다.

### `processing` · 생성 처리 중

시작 후 30분 이내라면 기다립니다. 30분이 지났고 Vercel 로그와 OpenAI 요청 상태를 확인한 뒤 실제 처리가 끝나지 않았다고 판단한 경우에만 다음 순서로 처리합니다.

1. 복구 사유 입력
2. `오래된 처리 건을 실패로 전환` 선택
3. 확인 창에서 승인
4. 상태를 다시 조회해 `failed` 확인
5. 아래 실패 건 절차 수행

### `failed` · 생성 실패

오류 코드와 OpenAI 요청 ID를 먼저 확인합니다. 중복 결과가 생성되지 않았다고 판단한 경우에만 다음 순서로 처리합니다.

1. 복구 사유 입력
2. `이 결제에 1회 재시도 허용` 선택
3. 확인 창에서 승인
4. 고객에게 미래좌표 결과 화면에서 `다시 시도하기`를 누르도록 안내

### `retry_allowed` · 1회 재시도 허용됨

고객이 다시 시도하기 전입니다. 고객이 실행하면 상태가 `processing`으로 바뀌고 재시도 횟수가 1 증가합니다. 같은 권한은 다시 사용할 수 없습니다.

### `completed` · 생성 완료

재시도를 허용하지 않습니다. 현재 서비스는 생성 결과를 고객 브라우저에만 저장하므로 결과 분실 문의는 별도 확인 후 환불 또는 별도 지원 절차로 처리합니다.

## 장애 확인 정보

생성 장부에는 인터뷰 원문과 실제 결제번호를 저장하지 않습니다. 다음 진단 정보만 저장합니다.

- 생성 상태와 시각
- 내부 시도 ID
- 오류 코드
- OpenAI `x-request-id`
- 자체 `X-Client-Request-Id`
- OpenAI HTTP 상태 코드
- 재시도 횟수와 복구 이력

OpenAI 요청 ID 기록은 운영 장애 조사 시 요청을 식별하기 위한 것입니다. 자세한 배경은 [OpenAI API 요청 디버깅 문서](https://developers.openai.com/api/reference/overview#debugging-requests)를 참고합니다.

## 금지 사항

- 결제 승인 확인 없이 재시도 허용
- 30분이 지나지 않은 `processing` 기록 강제 중단
- `completed` 기록 재생성
- 고객의 인터뷰 답변을 복구 사유에 기록
- 운영 복구 비밀키를 브라우저 저장소나 Git에 저장
- Redis 값을 콘솔에서 직접 삭제하거나 수정
