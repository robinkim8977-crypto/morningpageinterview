# GA4 홍보 전 퍼널 설정

## 코드에서 기록하는 이벤트

| 이벤트 | 기록 시점 | 주요 용도 |
| --- | --- | --- |
| `page_view` | 페이지가 바뀔 때 | 경로별 방문 확인 |
| `interview_start` | 미래 시점과 이름을 입력하고 인터뷰룸에 입장할 때 | 인터뷰 시작률 |
| `interview_complete` | 11번째 질문을 저장하고 인터뷰를 완료할 때 | 인터뷰 완주율 |
| `report_generated` | 무료 리포트 또는 미래좌표 리포트가 준비될 때 | 결과 제공 완료율 |
| `view_item` | 미래좌표 구매 영역을 이용할 수 있을 때 | 상품 조회 |
| `begin_checkout` | 약관 동의 후 결제창을 요청할 때 | 결제 시작률 |
| `purchase` | 서버에서 결제 승인을 확인한 뒤 | 실제 구매와 매출 |
| `payment_error` | 결제 요청·PG 응답·리디렉션·승인 검증 실패 시 | 결제 장애 구간 |
| `report_error` | 미래좌표 생성 실패 시 | 생성 장애 확인 |
| `pdf_download` | 무료 또는 미래좌표 리포트의 PDF 저장을 누를 때 | 결과 활용도 |
| `first_action_committed` | 72시간 첫 행동을 저장할 때 | 후속 행동 전환 |

인터뷰 이름·답변, PortOne 결제번호, PG 오류 원문은 전송하지 않습니다. `purchase`의 `transaction_id`는 PortOne 결제번호가 아니라 분석 전용 무작위 번호입니다. 페이지 조회도 검색어를 제거한 경로만 전송합니다.

## 1. 중복 페이지뷰 방지

앱이 페이지 변경을 직접 기록하므로 GA4의 브라우저 기록 변경 자동 감지를 끕니다.

1. [Google Analytics](https://analytics.google.com/)에 로그인합니다.
2. 왼쪽 아래 `관리`를 누릅니다.
3. 화면 위쪽 속성 선택기에서 운영 사이트의 GA4 속성을 선택합니다.
4. `데이터 수집 및 수정` 아래 `데이터 스트림`을 누릅니다.
5. 운영 사이트의 `웹` 스트림을 누릅니다.
6. `향상된 측정` 오른쪽의 톱니바퀴를 누릅니다.
7. `페이지 조회` 행에서 `고급 설정 표시`를 누릅니다.
8. `브라우저 방문 기록 이벤트를 기반으로 한 페이지 변경`을 끕니다.
9. 오른쪽 위 `저장`을 누릅니다.

페이지 로드 자체의 자동 측정 설정은 그대로 두어도 코드의 `send_page_view: false`가 기본 페이지뷰를 막고, 앱이 개인정보를 제거한 `page_view`를 보냅니다.

## 2. 맞춤 측정기준 등록

1. 왼쪽 아래 `관리`를 누릅니다.
2. `데이터 표시` 아래 `맞춤 정의`를 누릅니다.
3. `맞춤 측정기준` 탭을 선택합니다.
4. `맞춤 측정기준 만들기`를 누릅니다.
5. 아래 표의 값을 한 줄씩 등록하고 매번 `저장`을 누릅니다. 범위는 모두 `이벤트`입니다.

| 측정기준 이름 | 범위 | 이벤트 매개변수 |
| --- | --- | --- |
| 결제수단 | 이벤트 | `payment_method` |
| 리포트 종류 | 이벤트 | `report_type` |
| 리포트 생성 방식 | 이벤트 | `generation_source` |
| 결제 오류 단계 | 이벤트 | `error_stage` |

고유한 거래번호나 사용자 식별자는 맞춤 측정기준으로 만들지 않습니다.

## 3. 핵심 이벤트 등록

1. 왼쪽 아래 `관리`를 누릅니다.
2. `데이터 표시` 아래 `이벤트`를 누릅니다.
3. `이벤트 만들기`를 누릅니다.
4. 코드에서 보내는 새 이벤트를 등록하는 선택지가 보이면 `코드로 만들기`를 선택합니다.
5. 이벤트 이름에 `interview_complete`를 입력하고 `주요 이벤트로 표시`를 켭니다.
6. `기본 주요 이벤트 값 설정 안함`과 `이벤트당 한 번`을 선택한 뒤 `만들기`를 누릅니다.
7. 같은 방식으로 `report_generated`를 등록합니다.

`purchase`가 이미 목록에 있고 별표 또는 주요 이벤트 표시가 켜져 있다면 중복으로 만들지 않습니다. 아직 `코드로 만들기` 선택지가 없고 기존 이벤트의 일치 조건만 요구한다면 이벤트를 복제하지 않습니다. 코드를 먼저 배포하고 해당 이벤트가 수집된 후 `이벤트` 목록에서 별표 또는 `주요 이벤트로 표시`를 켭니다.

## 4. 배포 후 수집 확인

1. 코드가 운영 배포되어 Vercel 상태가 `Ready`인지 확인합니다.
2. GA4 왼쪽 메뉴에서 `보고서`를 누릅니다.
3. `실시간`을 누릅니다.
4. 새 시크릿 창에서 운영 사이트를 엽니다.
5. 미래 시점과 테스트용 이름을 입력하고 `인터뷰룸 입장하기`를 누릅니다.
6. 실시간 보고서의 `이벤트 이름별 이벤트 수`에서 `page_view`와 `interview_start`를 확인합니다.
7. 미래좌표 상품 페이지를 열고 `view_item`을 확인합니다.

실결제 전에는 `begin_checkout`와 `purchase` 확인을 위해 결제 버튼을 누르지 않습니다. 카드 및 간편결제 실결제·취소 테스트 때 함께 확인합니다.

## 5. 홍보 후 볼 두 가지 퍼널

GA4 `탐색`에서 아래 두 퍼널을 분리하면 구매 선후 관계가 달라도 해석하기 쉽습니다.

- 인터뷰 퍼널: `interview_start` → `interview_complete` → `report_generated`
- 구매 퍼널: `view_item` → `begin_checkout` → `purchase` → `report_generated`

맞춤 매개변수는 등록 후 일반 보고서에 반영되기까지 시간이 걸릴 수 있으므로, 당일 확인은 실시간 보고서를 사용합니다.
