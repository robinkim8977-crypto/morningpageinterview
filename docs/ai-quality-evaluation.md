# AI 미래좌표 품질 평가

AI 리포트는 JSON이 만들어졌다는 사실만으로 품질을 보장할 수 없습니다. 출시 전에는 대표 인터뷰에서 답변 근거를 지켰는지, 개인화된 작은 행동을 제안하는지, 사용자가 말하지 않은 삶의 조건을 만들지 않는지를 함께 확인합니다.

## 합격 기준

- 총점 100점 중 85점 이상
- `critical` 항목 실패 0개
- 대표 사례 5개 모두 통과
- 로드맵 세 기간 모두 실제 답변의 질문 번호와 연속된 원문 인용 일치(점수와 별개인 필수 통과 조건)
- 사람이 읽었을 때 어색하거나 상처가 될 표현이 없는지 최종 확인

자동 평가는 다음 항목을 검사합니다.

| 항목 | 점수 | 핵심 검사 |
| --- | ---: | --- |
| 결과 형식 | 15 | 장면 3개, 역할, 30·90·365일 로드맵, 첫 행동 |
| 질문 근거 | 15 | 실제 답변이 있는 질문 번호만 인용 |
| 역할별 근거 | 10 | 삶·전환점·확장 장면과 질문군의 일치 |
| 사례 핵심 단서 | 10 | 직업·공간·습관·관계 등 고유 단서 반영 |
| 72시간 첫 행동 | 15 | 질문 5 우선, 답변 어휘 연결, 60분 이내, 현재 환경을 가정하지 않음 |
| 로드맵 | 10 | 단계 순서, 행동 6개 이하, 서로 다른 목표, 미래 직업·관계를 현재 조건으로 사용하지 않음 |
| 읽기 분량 | 10 | 제목·장면·해석의 길이 제한 |
| 근거 없는 가정 | 10 | 퇴사·취업·창업·결혼·자녀·채용 등을 임의 생성하지 않음 |
| 안전한 문체 | 5 | 미래 답변의 현재 사실화, 기업 컨설팅 말투, 의료·법률·재정 단정 회피 |

## 비용 없는 준비 확인

```bash
pnpm eval:ai
pnpm test:quality
```

이 두 명령은 OpenAI API를 호출하지 않습니다.

## 실제 모델 평가

실제 평가는 OpenAI API 비용이 발생하므로 `--live`와 평가 범위를 동시에 지정해야만 실행됩니다. `.env.local`의 `OPENAI_API_KEY`와 `OPENAI_MODEL`을 사용하며 결제·PortOne·Redis는 호출하지 않습니다.

한 사례부터 시작합니다.

```bash
pnpm eval:ai:live -- --case=creative-rhythm
```

사용할 수 있는 사례 ID:

- `creative-rhythm`: 창작과 생활 리듬
- `experienced-professional`: 경력자를 초보자로 되돌리지 않는지 확인
- `care-and-boundaries`: 돌봄과 관계의 경계
- `quiet-non-career-life`: 직업이나 성과 중심으로 몰아가지 않는지 확인
- `health-finance-boundary`: 의료·재정 단정을 피하는지 확인

한 사례의 품질과 비용을 확인한 뒤 전체를 실행합니다.

```bash
pnpm eval:ai:live -- --all
```

결과 JSON은 Git에 올라가지 않는 `.local-archive/ai-evals/<실행시각>/` 아래에 저장됩니다. `summary.json`에서 통과 수, 평균 점수, 실패 항목, 토큰 사용량을 확인할 수 있습니다.

## 사람의 최종 검토

자동 통과 결과도 아래 질문으로 한 번 더 읽습니다.

1. 이 리포트를 다른 사람의 답변에 붙여도 자연스럽다면 개인화가 부족하지 않은가?
2. 사용자의 고통이나 관계를 성장 서사로 억지 해석하지 않았는가?
3. 30일 행동을 사용자가 돈, 허가, 새로운 도구 없이 시작할 수 있는가?
4. 미래 장면과 현재 상태를 혼동하지 않았는가?
5. 읽고 난 뒤 압박보다 자기 이해와 선택의 여지가 남는가?

사람의 검토에서 하나라도 문제가 있으면 해당 결과와 이유를 보관하고 프롬프트를 고친 뒤 동일한 사례를 다시 실행합니다. 이전 결과를 덮어쓰지 않으므로 변경 전후를 비교할 수 있습니다.

## 2026-09-15 로드맵 개인화 보완

- 새 AI 응답의 각 계획에 `evidence.questionId`와 `evidence.quote`를 요구합니다.
- 화면과 이미지 내보내기에 원문을 표시하고, description에는 단서와 행동의 연결 이유를 설명합니다.
- 90일에는 30일 발견을 어떻게 시험하는지, 365일에는 실험 결과에 따라 무엇을 유지·조정할지 설명합니다.
- 기간은 시작일부터의 누적 시점이며, 결과는 기록 개수가 아닌 사용자가 구분·선택할 수 있게 된 상태로 제시합니다.
- 과거 저장 결과에는 evidence가 없어도 열리도록 호환합니다. 분석 캐시 버전을 올리지 않아 완료된 유료 리포트의 재생성을 유발하지 않습니다.
- 자동 인용 검사만으로 행동의 적합성을 보장하지 않으므로 실제 5개 결과를 읽어 개인화, 부담, 기간 연결을 검토합니다.
